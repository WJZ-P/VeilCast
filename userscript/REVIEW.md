## 待处理

### [P1] 同名输出被静默覆盖

位置：`app/src-tauri/src/ffmpeg.rs` 的输出命名和 encoder `.arg("-y")`（当前第 354、376、441–443 行）。

扰乱输出只用输入 stem、tile、margin 命名，seed 不在文件名中；还原输出固定为 `stem.restored.mp4`。
同一文件换 seed 再运行、或输出目录已有同名文件时，ffmpeg 会直接覆盖旧文件，前端没有覆盖确认。
建议默认禁止覆盖或分配唯一输出名，再提供显式的覆盖选项；写入临时文件并成功后移动，可减少失败时留下半成品的风险。
本轮仅记录，未修改桌面输出策略。

### [P2] 文件切换的异步结果缺少过期校验

位置：`app/src/App.tsx` 的 `onFile`，尤其 `await probeVideo(path)` 后写入 `info/settings` 及截图请求完成后写入 `snapshots`。

连续选择 A、B 两个文件时，较慢的 A 请求可能在 B 之后完成；此时 file 已是 B，界面却可能显示 A 的尺寸、预览或错误。
处理调用再从当前 settings 取参数，会出现尺寸不匹配。建议用请求序号校验每次 await 的结果，丢弃过期响应并释放过期截图 URL。
本轮仅记录，未改动桌面交互流程。

## 本轮修复

### Rust / JS seed 解析不一致

Rust 的 `u64::from_str` 接受 `+007`，原 JS 只识别无符号数字；JS 的正则 `$` 又可能在结尾换行之前匹配。
这会让相同输入在两端得到不同排列。现在 JS 使用完整匹配，接受 Rust 支持的前导 `+`，其余文本按完整 UTF-8 做 FNV-1a。
同时去掉开发 viewer 的 seed `.trim()`，新增两端边界用例。

### WebGL shader 生命周期不完整

原还原器没有删除编译后的 shader，初始化失败时也未完整释放程序等资源。
现在链接后分离并释放 shader，失败路径清理资源，destroy 可重复调用；节点测试覆盖编译、链接、纹理分配和上传失败。

## 设计确认

- `permutation[scrambled_block] = original_tile`，浏览器构造逆映射，margin 仅在读取时扣除。
- 插件与 Tauri 共用默认配置文件，构建校验避免安装产物与源代码漂移。
- 平台转码后，仅三个参数不足以唯一确定原始尺寸。因此面板保留高级宽高输入，默认 720×1280。
- 线上播放器结构以用户给出的截图为依据；本轮运行验证使用本地相同层级的 DOM 和合成视频，实际平台/油猴环境仍待实测。
